## 到達点

`model.py` のクラスをimportし、層の構造を表示する。MNISTのデータを用意し、訓練・検証・テストの目的を理解する。学習ループを読みながら実行し、選んだ重みをファイルへ保存、新しいインスタンスへ読み込んでテストする。

読解・操作を含め約60分。取得後の学習と評価はCPUで2〜3分以内を目標にする。初回取得・依存導入は別。前章を読んでいてもデータ分割などの理解を省略せず、この章だけでも各操作の目的を説明する。

## 教材の形式

- `app.py` では05を `edit` モードで開く。学習者が実際のPythonセルを読み、Shift+Enterで実行する。
- 実習用の実行ボタン、subprocessによる学習、結果切り替えUIは使わない。
- `model.py` のみ、実ファイルから読む行番号付きのプレビュー。定義のコードを教材用に複製しない。
- その下の実行セルに `from model import MLP`、`model = MLP()`、`print(model)` を置く。`demo_import.py` は廃止。
- ライブラリのimport、MNIST取得、前処理、分割、DataLoader、損失関数、検証関数、学習ループ、保存、読み込み、テスト、作図を実際のコードセルにする。
- 本編は関数の一行呼び出しで学習内容を隠さない。損失計算と1回更新の短い実行例で部品を説明してから、`train_mnist` の全定義と呼び出しを同じセルに表示する。全定義にはimport・データ取得・前処理・分割・DataLoader・モデル・損失関数・optimizer・検証関数・学習が含まれ、前のセルの変数に依存しない。再実行は初期値から学習する。
- 自動的な後続実行を止めるlazy設定をこのnotebookに持たせる。アプリ経由では初回に全セルを実行し、実際のファイル表示・出力・曲線を最初から読めるようにする。この動作と、Run allも全工程の実行であることを冒頭に明記する。

## 説明の順序

| 順序 | 目的と説明 |
|---|---|
| 1. ファイルとimport | 必要最小限のフォルダ図。相対パスと現在地、importのモジュール名との違い。実際のモデル定義とprint出力を対応付ける |
| 2. クラスと継承 | クラスとインスタンス、self、初期化、forwardを具体的な層に沿って説明。nn.Moduleが重みを管理する理由を示す |
| 3. MNIST | 画像と正解の組を見せてからTensorへ。shape、画素値/255、型、軸の追加の意味を説明 |
| 4. データ分割 | 練習問題の丸暗記の例→過学習→未見の問題を残す理由→テスト→設定選択にも独立した検証が必要、の順 |
| 5. batchとepoch | 一度に小分けで処理する理由からDataLoaderへ。40,000枚を128枚ずつ、313更新で1周と具体化 |
| 6. 学習 | 損失と正解率、optimizerと学習率を説明。検証関数を定義し、5行の更新を含む学習ループを実行 |
| 7. 曲線と保存 | 訓練・検証の損失を読む。検証最小の重みをdeepcopyで残す理由と、構造と数値を別々に保存する理由 |
| 8. 復元とテスト | 新しいMLPへload_state_dict。公式10,000枚で評価。先頭画像と誤分類画像を比較する |
| 9. 振り返り | 重みを変えた行、評価のみのデータ、model.pyと重みファイルの違いを説明できるか確認 |

各概念は「なぜ必要か→使うコード→出力の読み方」の順に扱う。単に「分けます」「保存します」で始めない。

## データ分割の説明上の注意

全てのデータを訓練し、同じデータで評価しても未知データへの性能を確かめられない。1〜2割をテストとして残すのは一例で固定の規則ではない。分割自体が過学習を防ぐわけではない。

MNISTは公式で訓練60,000・テスト10,000に分かれている。テストを最後まで残し、公式訓練をseed 42のrandpermで並べ替え、最初の5,000を検証、次の40,000を訓練とする。残り15,000は時間短縮のため未使用。重なりが0であることをセルの出力で確かめる。

設定選択にテストを繰り返し使うと、その問題にも間接的に適合する。検証は設定や保存するepochを選ぶために使う。短い5 epochで必ず過学習が見えるとは約束しない。

## パスとファイルの役割

本編は教材全体のルートから起動する。データ取得のセルで `Path("data")`、保存するセルで `Path("outputs/05-pytorch/notebook/mnist_mlp.pt")` を指定する。保存先のためにconfig.pyを先に読ませない。現在地とresolveした保存先は出力で確認できる。

## 性能と確認

モデルは784→128→10、ReLU、Adam、batch 128、学習率0.001、5 epoch、CPU 2スレッド。以前のCLI例で20k・30k・40k・55kを3 seedで検証し、40kを選定した記録は `assets/benchmarks.json` に保持する。

改訂では設定の再探索は行わず、分割の説明を単純なランダム分割へ変更。実際のnotebookを一巡してテスト96.34%を確認した。CLI例の96.43%との差は0.09ポイント。Windows実機と初学者による試読は引き続き未実施。
