# 02〜04の対話的な説明・再生仕様

[制作方針へ戻る](README.md)・[設計一覧へ戻る](../README.md)

状態：文章・数式・図を軸に、02の条件比較、03の静止比較図と反復更新の再生、04の計算過程の再生と更新前後の横並び比較へ仕様を更新（2026-09-11）。既存のAPI候補は2026-09-10にローカルのmarimo 0.24.0と公式資料で確認したもの。03はmarimoに埋め込んだSVGプレイヤーで履歴を再生する。実装の選択と確認結果は[03の実装・検証記録](../03_classification/validation.md)を参照。02・04の検証状況は各章の記録で管理する。

## 文章・数式・図で説明を進める

02〜04の中心は、回帰・モデル選択、分類・学習、NN・逆伝播の理解である。文章で目的と意味を説明し、数式の記号を定義し、小さな数値例と図で関係を示す。コードの入力・書き換え・行ごとの読解は要求しない。01のPython説明に必要だったコード量を基準にしない。

marimoのリアクティブ実行を使い、入力の変更をSVG・数式への数値代入・表・結果の読み方に同時に反映する。操作や再生は文章による説明を支える。APIの紹介や操作部品を増やすこと自体を教材の目的にしない。

## 基本例の説明と、必要な観察・再生

02・03は次の段階1〜3を基本にする。03は勾配降下法の反復更新だけを操作対象にし、その他は静止図にする。04は文章・数式・静止図で説明し、順伝播・損失・連鎖律・逆伝播・更新と再推論の計算過程にだけ再生デモを添える。各節に操作を一律に割り当てず、独立した自由試行も設けない。

| 段階 | 学習者に示すもの | 制作基準 |
|---|---|---|
| 1. 説明を読む | 知りたいこと、文章、記号の意味、基本例の式・図・結果 | 操作前でも意味が分かる。結論をスライダーの発見だけに任せない |
| 2. 条件を絞って確かめる | 一つの問いと、比較条件を固定した短い操作 | 変える前の見通し、変えた要因、図と数値の変化を対応付ける |
| 3. 結果を読む | 何が変わり、なぜそうなるかの文章と式 | 代表例の観察と、そこから言える範囲を示す |
説明中の短い操作・再生は式と図の近くに置く。過学習や発散などは、条件を選んだ代表例で示す。基本例の説明中は一度に一要因を変える。

| 章 | 文章・式・図で理解すること | 説明に沿った観察 |
|---|---|---|
| 02 | 予測、MSE、重回帰と多項式、汎化とモデル選択、正則化 | 固定点で直線・誤差を追い、固定分割で次数・λの代表例を比べる |
| 03 | 線形二値分類、尤度・最尤推定、勾配更新と学習率、バッチ・ミニバッチ・SGD、多クラス分類 | 重みを一回ずつ更新する一つの図。学習率と3手法の軌跡は静止図で比較する |
| 04 | 手書き数字の認識、線形モデルの制約とNNの利点、構造・順伝播・連鎖律・逆伝播・更新 | 隠れ層2層・各層3ニューロンの固定例で計算を再生し、更新前を左・更新後を右に並べて再推論する |

各章約1時間には文章の読解、代表例の観察、結果の説明を含める。03の学習率比較は静止図で説明する。03には「任意」の節や折りたたみを置かない。機械学習帳を読むことは求めない。詳細導出・追加探索は任意とし、重要な式と説明は折りたたまない。

## コードと再生の位置付け

初期表示は文章・数式・図・操作を主にする。02・04では「計算の中身を見る」から実際に使っているコードを参照できるようにし、03には補足とコードの折りたたみを置かない。コードが説明を助ける箇所にだけ短い注記を添え、書かせる演習や全セルの読解を本編に加えない。表示用の処理やAPIの説明は学習者向けの本文に持ち込まない。05で、ここまでの概念を一つの学習コードへ対応付ける。

全場面をアニメーションにする必要はない。02の条件比較にはスライダーや切り替え、03の反復更新と04の計算順序には手動送りと再生を使う。再生前に工程の全体図と一工程の説明を置き、停止図だけでも要点を読めるようにする。再生を眺めただけで理解したことにはせず、各工程に目的・数値代入・結果の読み方を添える。04のReLUと線形変換の合成は数式・静止図で説明し、切り替えやニューロン選択を要求しない。

## 03の再生操作

動く図は勾配降下法の一つだけ。初期状態＋9更新の合計10状態を使い、一回進むと必ず一回重みを更新する。「戻る」「進む」「ループ再生」の3ボタンとし、再生ボタンは再生中に「一時停止」へ変わる。初期停止、1.6秒ごとに一更新、末尾から先頭へループする。前後移動で停止し、先頭の戻る・末尾の進むは無効にする。停止後の古いタイマー通知は無視する。

表示は損失曲線、現在の点と傾き、更新回数・重み・損失の一行に絞る。速度・位置・条件変更・リセット・詳細モードは置かない。更新式と数値代入は図の前の本文に置き、計算工程ごとにコマを分けない。具体的な条件は[03の設計](../03_classification/README.md)に従う。

## 04の再生操作

04は「戻る」「進む」「自動ループ再生」の3操作だけとし、先頭ボタン・位置スライダー・速度選択は置かない。04の自動再生は最終結果を2秒表示してから先頭へ戻り、同じボタンで停止できる。数値は計算された時点で表示し、それまでは空欄とする。

図・式・数値・説明は一つのステップ番号から描画する。再生と手動送りで別の計算処理を持たない。「戻る」は記録した計算の参照であり、重みを逆更新する操作ではない。03は更新番号のみ、04は計算の工程名とステップ番号を表示する。

04の更新・再推論では左側の更新前を計算済みの状態で固定し、右側だけ更新後の重みで再計算する。両側の入力・正解・配置を揃え、一つのプレイヤーで対応箇所を強調する。左右を切り替えて片側を消す表示にはしない。04の動くNNはすべて隠れ層2層・各層3ニューロンに固定する。

一つのノートブックで複数のプレイヤーを同時に再生しない。03のプレイヤーは一つで、3手法は静止図とする。別のプレイヤーを開始したら前の再生を止める。画面から離れて戻っても大量のコマを飛ばさず、タイマー一通知につき最大一コマ進める。

## marimoの機能と実装上の役割

下記は制作側の実装方針であり、学習者にAPIの理解を要求しない。

04の固定履歴の再生は、`mo.iframe`へ埋め込むHTML部品を採用した。計算・SVG・説明はPythonで生成し、ブラウザは表示位置だけを変更する。以下の`mo.state`・`mo.ui.refresh`などは標準UIによる実装候補であり、04では停止・前後移動・自動ループ再生・プレイヤー間の停止通知を部品内で実装している。詳細と確認結果は[04の実装・検証記録](../04_neural_networks/validation.md)を参照。

| 機能 | 使う場面・役割 |
|---|---|
| `mo.ui.slider`、`mo.ui.number`、`mo.ui.dropdown` | 重み・学習率・次数・観察対象・ステップ位置を選ぶ。値とラベルを必ず表示 |
| `mo.ui.button` | 前後移動・先頭・再生状態の切り替えを明示的なイベントとして扱う |
| `mo.ui.refresh` | 自動送りの定期通知。通知間隔は描画・実行時間に左右されるため、厳密な動画フレームレートとして扱わない |
| `mo.state` | 再生状態、編集済みの点、比較用の変更前の結果、確定した最終評価など、保持が必要な状態を管理する候補。通常の数値変更はUI値のリアクティブな参照を優先し、保持する状態と初期化条件を明示 |
| `mo.ui.tabs`、`mo.accordion` | 図／数値表の切り替えや追加の導出。重要な説明を隠さず、タブ変更で学習を再実行しない |
| `mo.hstack`、`mo.vstack`、`mo.md`、`mo.Html` | 操作・SVG・数値代入・短い説明を並べる。通常は狭い画面で縦に読める配置とするが、04の更新前後は横並びを保持し、必要なら比較領域を横スクロールする |
| フォーム、`mo.ui.run_button` | まとめて適用する実験条件や任意の学習開始。スライダーを動かすたびに重い学習を走らせない |

スライダーと数値入力の仕様は[公式Slider API](https://docs.marimo.io/api/inputs/slider/)、操作ボタンは[Button API](https://docs.marimo.io/api/inputs/button/)、定期通知は[Refresh API](https://docs.marimo.io/api/inputs/refresh/)を参照する。状態の共有と再実行の挙動は[State API](https://docs.marimo.io/api/state/)を参照する。

点編集・変更前後の比較・最終評価の固定は制作時に小さく試作し、使用するAPIと挙動を確認する。表や選択部品だけで任意の点編集ができると仮定しない。

UIの定義、入力に基づく計算履歴の生成、選択ステップの表示を別のセルにする。UIの値は定義セルとは別のセルで読む。履歴の生成は再生位置やタイマーに依存させず、データ・パラメータ・計算条件だけに依存させる。

タイマー通知の処理では再生中かを確認し、一度処理した通知を再処理しない。停止・条件変更の後に届く旧通知は無視する。状態はsetter経由で変更し、描画セルでは更新しない。自己再実行ループや、コントロールの再生成による位置・速度のリセットを避ける。標準UIを使う場合は停止・再開・位置の同期を小さく試作して確認する。04の固定履歴の再生では、同じ受け入れ基準を埋め込み部品で確認した。

## 読みやすさと実行負荷

- 図の配置と比較する軸の範囲を固定する。自動拡大が必要な場合は範囲が変わったことを明示する。
- 色だけに依存せず、ラベル・矢印・線種を併用する。現在の演算と式を近くに置き、選択できる対象はマウスのホバー以外でも選べるようにする。
- 初期状態では自動再生せず、手動送りだけで全工程を読めるようにする。工程一覧と代表的な結果も残す。静的出力で再計算できないUIがある場合は明示する。03の埋め込み再生図はHTML出力でも操作できる。
- 数値表示の丸めと内部計算を分け、図と式の精度を揃える。未計算と値0を区別する。
- 小さなCPU計算と保存済み履歴で、操作後おおむね0.2秒以内の表示更新を目標にする。目標値は未実測。重い処理は開始ボタンと進捗表示を使い、再生中には実行しない。
- 説明例・比較例はデータ・seed・分割を固定する。
